一、项目与研究方法

DeepSeek Harness（dsh）是 DeepSeek AI 开源的 Agent harness，采用 Cordis 驱动的“一切皆插件”架构。本文不把提交数量直接当作产出，而是结合提交主题、时间分布、分支名称和 Release 内容，推断技术演进与协作流程。

重要限制：Git 历史会受到 merge commit、主干同步、机器人提交、作者/committer 不同和内部开源前积累影响；贡献量只能作相对判断，不能等同于工时或业务价值。

二、开发过程时间线

阶段 1：架构奠基（06-10 至 06-11）

初始化仓库、MVP 需求和微内核架构；建立 monorepo、TypeScript project references、Vitest、CI、严格类型、覆盖率与文档；引入 Cordis、抽象服务接口、Agent Loop 和 echo-agent。

特征：先定插件边界、服务接口和质量门禁，再写具体产品能力。

阶段 2：最小可运行 Agent（06-13 至 06-14）

加入 Bash、DeepSeek/pi-ai 模型适配、coding-agent 示例、工具参数校验、事件契约断言、Session log freeze、属性测试、结构化错误和文档同步检查；同时用 RFC 001、005、006、008、009-012 固化设计。

阶段 3：能力扩张与架构验证（06-15 至 06-30）

扩展 ACP、Code Mode、工具执行流水线、文件系统、进程、沙箱、PTY、持久化、配置和 Web 基础设施。任务通过 feat/、fix/、worktree/、codex/ 等小分支拆分。

阶段 4：从框架到完整产品（07-01 至 07-18）

集中建设 Web/TUI、多会话、会话恢复、文件编辑、LSP、子 Agent、Job、MCP/ACP、多模态、Web API、Session fork、目标管理和工作区上下文；底层 Agent inbox、事件、scope 和 Host/Client 边界仍同步演进。

阶段 5：工程硬化（07-18 至 08-10）

大量提交转向 Snapshot、E2E、Windows/macOS/Linux 兼容性、PTY、Web 细节、类型、构建、依赖、CI 和恢复边界问题，形成多条子系统并行工作流。

阶段 6：公开发布前产品化（08-10 至 08-17）

整理中英文 README、onboarding、安装升级、API key、Web 体验和 Windows CI；补齐图片附件、Job Panel、插件设置卡片、Safari、node-pty 和历史消息问题，发布 dsh-v0.1.0-rc.7。

三、团队协作方式

机制从历史看到的证据带来的效果
主干持续集成频繁出现 PR merge、同步 origin/master、冲突解决减少长期分叉，快速汇聚并行成果
Worktree 并行大量 worktree/* 分支，配合 codex/*、xtr/*不同开发者或 Agent 拥有隔离工作区，降低互相阻塞
RFC / ADR 驱动RFC 001、005、006、008、009-012 与架构决策文档先统一设计边界，再拆分实现，降低并发冲突
Review 驱动迭代提交信息反复出现 Codex review、review findings、review gaps把审查前置，快速修正设计和边界问题
自动化质量门禁类型、覆盖率、属性测试、Snapshot、E2E、文档和包校验用机器替代重复人工验证，支持更高提交频率
文档即工程资产架构文档、Agent Notes、双语 README、doc-sync 检查让多人和自动化 Agent 共享明确的上下文

五、效率来源与合理解释

  1. 公开仓库不一定等于项目起点：首日就有成熟架构、MVP、RFC、ADR 和质量门禁，说明可能存在开源前的内部设计或代码积累。
  2. 模块边界适合并行：LLM、Tool、Session、Sandbox、Shell、UI 和 API 都能按插件或 seam 拆开。
  3. 高并发工作流：worktree、小 PR 和持续主干同步降低等待时间。
  4. 自动化验证：类型、测试、Snapshot、文档和跨平台门禁让高频合并仍可控。
  5. AI 辅助可能参与：Codex、Agent、worktree 等痕迹明显，但 Git 历史无法准确区分人和 AI 的代码贡献比例。

六、总体判断

更准确的描述是：一个已有较强内部积累的核心团队，通过插件化架构、RFC/ADR、worktree 并行、自动化质量门禁、持续主干集成和 AI 辅助 Review，在约两个月内完成了公开化、工程化和产品化。

值得借鉴的不是单纯的“提交速度”，而是：

前置架构设计 + 清晰插件边界 + 小步 PR + 并行工作区 + 自动化验证 + 持续集成 + AI 辅助。
